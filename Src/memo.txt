■インライン展開
コンパイル時に関数の呼び出し部分をその関数の実際の処理コードに直接置き換える
コンパイラーの最適化技術。
通常は関数を呼び出すとプログラムは別の場所に処理を
ジャンプさせるが、インライン展開をするとそのジャンプがなくなる。
メリットは実行速度が速くなること。
関数呼び出しには現在の処理位置をメモリに一時保存するや、
関数の場所へ処理をジャンプ、終わったら元の場所にジャンプなど
オーバーヘッドがかかっている。


■テンプレート
テンプレートは定義をヘッダに書かなければならない。
テンプレート単体では機械語（コンパイル済みコード）になれないため。
テンプレート内で別クラスの関数などを呼び出している場合は、
そのクラスが定義されているｈファイルをインクルードしないといけない。
先行宣言だけでは、そのクラスのサイズやメンバ変数が分からないため。


■Partition
std::partition : 元の配列の順番を維持せずにグループ分けする
				 高速に処理可能、メモリ消費０
std::stable_partition : 元の配列の順番を維持しつつグループ分けする
				 処理少し遅い、メモリを一時的に消費



■explicit
コンストラクタにつける予約語。暗黙の型変換を禁止する
例：
class MyArray {
public:
    // 引数1つのコンストラクタ（explicit なし）
    MyArray(int size) { /* size分のメモリを確保 */ }
};

void printArray(MyArray arr) { /* 配列を表示する関数 */ }

int main() {
    // ① 本来の意図：サイズ10の配列を作る
    MyArray a = 10; // 動いてしまう（intの10からMyArrayが自動生成される）

    // ② 危険な例：プログラマの書き間違い
    // 本来はオブジェクトを渡すべき関数に、間違えて数値を渡してしまった
    printArray(20); 
    // コンパイラが勝手に「サイズ20のMyArray」を一時的に作って関数に渡してしまう！
    // コンパイルエラーにならず、実行時に意図しないメモリ確保が起きてバグになる。
}


■ユーザー定義型の型変換演算子
例：operator GLuint() const { return id; }
GLuint型の引数を求めている関数などにこのクラスのオブジェクトを
渡すと自動的にGLuint型にキャストしてくれる


■GLintptr
OpenGLで使われるポインタと同じサイズを持つ符号付き整数型
32bitや64bit環境でポインタのサイズが異なる（4バイトと8バイト）
そのため、通常のInt（常に4バイト）を使用すると64ビット環境でメモリのアドレスを
正しく扱えない可能性がある
